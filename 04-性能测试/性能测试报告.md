## 三、瓶颈分析 & 调优措施（重点内容，面试重点）

### 3.1 瓶颈 1：报名缴费接口 TPS 38 → 420（最严重）

**症状**：
- CPU 应用 3 节点都达到 **95%+**，Load Average 12/18/25（8C 机器正常应<8）
- Arthas flame graph 火焰图 **`HashMap.resize()`** 占用 42% CPU
- GC 日志：**Full GC 8次/10分钟**，每次耗时 1.2s~2.8s，停顿严重

**根因排查（面试可讲）**：
1. **代码热点**：报名计算优惠时，使用了非线程安全的 `HashMap` 在多线程下扩容导致 CPU 飙升
2. **缓存缺失**：课程、优惠券、满减规则每次都查库，DB QPS 3000+ 压力大
3. **事务过大**：创建订单 + 扣减课时 + 生成流水 + 扣减库存 放在一个大事务中，锁冲突严重

**调优措施**：
| # | 措施 | 负责人 | 效果 |
|---|------|--------|------|
| 1 | `HashMap` → `ConcurrentHashMap`，优惠计算对象改为 ThreadLocal | 后端·王工 | CPU usage ↓20% |
| 2 | 课程/优惠券/满减规则加入 **Redis 本地二级缓存（Caffeine + Redis）**，TTL=5min | 后端·苏绍彰协助 | DB QPS ↓70% |
| 3 | 大事务拆分：主订单 1 事务 → 课时异步处理（MQ）→ 流水异步处理 | 后端·架构 | 锁冲突 ↓90% |
| 4 | JVM 参数：-Xms8g -Xmx8g -XX:MaxMetaspaceSize=512m + G1 GC `MaxGCPauseMillis=200` + 关闭偏向锁 | 运维 | Full GC 0次/10min |
| 5 | 数据库表 `t_enrollment` 创建联合索引 `idx_student_campus_status`（原没有索引，全表扫描） | DBA·周工 | 查询成本从 9.8s → 0.05s |

### 3.2 瓶颈 2：财务日报查询 P95 12.44s → 2.35s

**根因**：
- 报表 SQL 使用了 3 层嵌套子查询 `WHERE date IN (SELECT ...)`，执行计划 filesort + temporary
- `t_payment` 表 80 万数据，索引只建在 id 上，按日期扫全表
- 主库查询，和业务读写抢资源

**调优方案**：
| # | 措施 | 效果 |
|---|------|------|
| 1 | 联合索引：`(pay_time, status, campus_id, pay_method)` 覆盖索引 | 避免回表 |
| 2 | SQL 改写：3 层子查询 → JOIN + GROUP BY + 临时派生表 | rows 80w→1.2w |
| 3 | 读从库查询，配置 `@DS("slave")` 动态数据源 | 主库无压力 |
| 4 | 报表预计算，每日 02:00 定时任务生成前一天报表结果表 | 实时查询→KV 查 10ms |

### 3.3 瓶颈 3：登录 P95 3.28s（token 生成慢）

**根因**：
- token 每次登录都查 **3 次 DB**（用户 + 角色 + 权限菜单）+ 密码 BCrypt 校验
- 500 并发下 BCrypt cost=12 的计算耗时 200~400ms 累计

**调优**：
- 权限菜单加入 Redis 缓存，TTL=1h + 主动刷新机制（菜单变更）
- BCrypt 改为 cost=11 + 登录失败 5 次锁定策略不变
- 数据库连接池 HikariCP `maximumPoolSize=20 → 80`（之前太小，排队等待）

## 七、遗留风险 & 生产上线建议

### 7.1 遗留风险
| # | 风险 | 影响 | 规避方案 |
|---|------|------|----------|
| 1 | 500 并发通过但 1000 并发 错误率上升到 1.2%（未达标） | 极端开学日可能 | 开启网关限流：单 IP 100/s，全局限流 800 TPS |
| 2 | 报表查询如果 SQL 不规范（比如自定义时间段跨年），P95 偶发 6s | 部分操作员工 | 报表时间范围限制≤90天，超过走异步导出任务 |
| 3 | MySQL 主从延迟压测峰值达到 3.2s | 读从库场景下暂时数据不一致 | 关键业务（比如缴费后立刻查订单详情）强制读主库 |

### 7.2 生产上线建议
1. ✅ **必做**：上线前把本次调优的 SQL 索引、JVM 参数、缓存配置、连接池参数全部同步到生产配置中心
2. ✅ **必做**：Grafana + Prometheus 配置 生产性能大盘 ，告警阈值与本次一致
3. ✅ **必做**：准备 **3 台施压机 + 1 台 JMeter Controller**，开学前一周进行**生产全链路压测（限流模式）**
4. ⭐ 建议：报名缴费接口准备**降级开关**（非核心链路：推荐奖励、课酬预计算、模板消息，异常时可降级）
5. ⭐ 建议：开学高峰当日 SRE + DBA + 测试 联合值守
